# Test the status

Before anything goes to a sponsor: check the claims, the dates, the impact of a slip, and whether a change needs approval.

| Skill | What it does | Claude upload |
| --- | --- | --- |
| **[challenge-my-status](./challenge-my-status/SKILL.md)** | Check a draft status report against the last approved report and the supporting evidence, and pick out the few claims a PM should challenge before sending, with both sources and replacement wording. | [Download](https://github.com/jsconu/pmo-skills/releases/latest/download/challenge-my-status.zip) |
| **[reconcile-the-dates](./reconcile-the-dates/SKILL.md)** | Line up the dates in a schedule, a customer commitment and a delivery forecast, work out which refer to the same milestone, show the gap, and say what still needs approval. | [Download](https://github.com/jsconu/pmo-skills/releases/latest/download/reconcile-the-dates.zip) |
| **[review-a-change-request](./review-a-change-request/SKILL.md)** | Review a proposed scope, backlog or schedule change against the baseline, identify which committed deliverables and milestones it touches, and route the decision to the right approver. | [Download](https://github.com/jsconu/pmo-skills/releases/latest/download/review-a-change-request.zip) |
| **[trace-the-impact](./trace-the-impact/SKILL.md)** | Trace an upstream slip or change through its dependencies to find which downstream work is exposed, which can still proceed, and how much buffer is left. | [Download](https://github.com/jsconu/pmo-skills/releases/latest/download/trace-the-impact.zip) |
