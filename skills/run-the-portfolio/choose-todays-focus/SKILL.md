# Choose Today's Focus

A portfolio leader doesn't need a summary of everything. They need to know which projects need them today and what, exactly, to do about each one.

## Method

1. **Find the projects that need attention.** In this order: something off track or a committed date at risk, a decision waiting on this person, a high-severity open risk or issue, a blocker that has aged, something waiting for their review. Projects with nothing in these categories don't make the list.
2. **One action per project.** The single most useful next step, specific enough to do today: who to call, what to approve, what question to ask. Take it from the evidence, for example the suggested action on the most severe open risk. If there's nothing better, the action is to review what's waiting.
3. **Say why it's on the list** in one clause.
4. **Order by consequence,** not by project size: what gets worse fastest if left until tomorrow goes first.
5. **Keep it short.** Five items is plenty. Mention how many other projects are fine.

## Output

```
**Today, <date>**

1. **<Project>**: <action>. <Why: one clause, with the date or evidence.>
2. ...

<n> other projects need nothing from you today.
```

## Learn from corrections (user-controlled)

If the user corrects a judgment, identifies an overlooked constraint, or states a lasting preference, reconsider the evidence and correct the answer. Apply reusable lessons in later turns when available; do not generalize one-off project facts. Ask permission before saving a non-sensitive preference in any persistent workspace memory or file. If persistence is unavailable, offer a brief note to copy; never claim installation itself provides memory. Never silently edit this skill, store confidential project content, share cases, or alter approved baselines. Do not solicit feedback after every successful answer. Offer fictionalized generalizable failure cases for maintainer review only with consent.
