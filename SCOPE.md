# Scope

This repo is a curated set of PMO methods. Ideas are welcome, and each is judged against the bar below.

## The bar

A change to a skill is taken up only if it clears **both** parts:

1. **Observed case.** It describes a real failure, written as a fictional case: what you pasted (anonymised), what the skill said, and what an experienced PM would have done instead. "It would be better if..." does not clear this part.
2. **Fits the method.** It keeps the skill working from material the user supplies, it doesn't depend on one tool or one company's process, and it doesn't trade accuracy for a longer answer.

## New skills

Suggestions are welcome as [ideas](https://github.com/jsconu/pmo-skills/issues/new?template=idea.yml). A new skill joins `in-progress/` only when there is a clear moment it serves and four fictional cases to test it on. It is promoted only after it beats a plain assistant in a blind review (see [evals/](./evals/README.md)).

## Out of scope

Each file in [`.out-of-scope/`](./.out-of-scope/) records one rejected idea and why.

- [`connectors-and-sync.md`](./.out-of-scope/connectors-and-sync.md)

## Unclear issues

An issue that can't be judged against the bar gets one round of questions and the `needs-info` label. With no reply in 14 days, it is closed.
